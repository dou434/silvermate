# 作品功能与作品创新性

> 适用：竞赛申报表 / 作品说明 / 答辩材料。口径与当前代码（v0.7.1.beta1）一致；医疗表述按 `docs/contest/00_材料清单与待办.md` 的合规要求处理，不使用「诊断、治疗、替代医生」等措辞。

## 一、作品功能

### （一）作品定位

「银发智伴」是一套面向居家养老场景的双端 AI 助手：老人用一句大白话就能问知识、办事情、求助；子女在同一套系统里为老人安排提醒、查看执行情况、接收紧急消息。

它不是一个只会聊天的对话框，而是把 **AI 对话、养老知识库、提醒执行、家庭协同、紧急求助** 串成一条可运行、可演示的闭环：老人说一句话，系统能落到一条真实的提醒、一条真实的留言、一次真实的求助；子女打开页面，能看到今天发生了什么、老人有没有照做。

### （二）用户角色

| 角色 | 进入方式 | 核心诉求 | 系统提供 |
| --- | --- | --- | --- |
| 长辈（老人） | 注册时选「我是长辈」，登录进入老人端 | 看得清、听得懂、按得动；有事能问、能办、能求助 | 今日提醒、到点提醒、一句话办事、AI 顾问、SOS、家人留言 |
| 子女（家属） | 注册时选「我是子女」，登录进入家人端 | 不在身边也知道老人今天怎么样 | 绑定老人、安排提醒、今日状态与完成率、留言、紧急提醒 |
| 照护者 / 管理员 | 管理账号 | 维护知识与模型、观察运行情况 | 知识库、模型管理、用户与权限、任务中心 |

老人端与子女端不是两个 App，而是同一套账号体系按身份进入不同首页，降低部署与使用成本。

### （三）功能总览

- **交互层**：老人端首页、家人页、问 AI；子女端「今日状态 / 提醒管理 / 留言」；适老化设置；问 AI 页面的 SOS 浮动按钮。
- **智能层**：唯一的「银发智伴」智能体、一句话指令路由、养老知识库检索、老年评估与护理计划 Skills、家庭数据只读工具。
- **业务层**：提醒与执行记录、家庭绑定与授权、留言与转达、紧急事件。
- **平台层**：多模型接入、知识库与文档解析、知识图谱与思维导图、多租户权限、Docker Compose 一键部署、演示数据脚本。

### （四）核心功能

#### 1. 老人端：今天要做什么，一眼看清

- 首页按时间段问候，今日提醒按时间排序，显示时间、标题、说明、分类标签（用药 / 复诊 / 饮食 / 活动），并标注「家人提醒」或自己创建。
- 每条提醒都有明确出口：未到点或刚到点显示「我收到了」；已确认后显示「做完了 / 没做到」；完成后展示结果，可补一句备注。
- 到点提醒不是一条静默通知：弹窗 + 合成铃声 + 中文语音播报，例如「下午五点三十九分，提醒您吃降压药」。同一分钟多条提醒依次弹出、不重复；页面切到后台时暂停轮询，切回来立即补刷。
- 适老化设置：标准 / 大字 / 超大字三档字号，四套主题色与深色模式；聊天页支持语音输入，AI 回复可自动朗读；提醒铃声与提醒语音可分别开关，默认开启。
- 「我的家人」页可同意或拒绝子女的绑定申请、查看留言；「问 AI」页面提供常驻 SOS 浮动按钮，随时可发起求助。

#### 2. 子女端：看得见的照护

- 输入老人 UID 发起绑定，**必须老人本人同意后才生效**；支持同时照护多位老人并随时切换。
- 今日状态：近 7 天完成率、已完成 / 未完成 / 待确认计数、逐日柱状图、今日提醒清单与老人备注。
- 提醒管理：新建、修改、删除；支持只提醒一次、每天、每周几、自定义间隔与结束日期；分类覆盖用药、复诊、饮食、活动。老人申请「改时间 / 停用」后，子女在留言卡片上一键确认即可生效。
- 老人自己创建的提醒，子女只能查看、不能改，界面明确提示「老人自己创建，仅可查看」。
- 留言：未读角标、对话气泡、系统转达卡片；紧急事件在页面顶部以红色横幅常驻，显示未处理数量、来源（SOS 按钮 / 聊天提到）、急症分类、老人原话与时间。

#### 3. 一句话办事：不学菜单，说人话就能用

老人不必理解「提醒管理」「留言板」这些概念，直接说：

- 建提醒：「提醒我明天早上八点吃药」「每天下午三点提醒我喝水」
- 改提醒：「把吃药提醒改到下午三点」
- 停提醒：「别再提醒我吃药了」
- 确认与完成：「我收到了」「吃药做完了」
- 给家人留言：「告诉小明今晚我晚点回去」
- 打开页面：「打开家人」「回到提醒」

系统会区分「问方法」与「下指令」：「怎么给小明发消息」交还给 AI 正常回答，不会误发留言；时间说不全（如「大后天」「隔天」「每月」）时不猜，改为追问；缺事项、缺时间也追问。命中指令后直接完成服务端写操作，前端只负责刷新界面。

当老人想改的是**子女设置的提醒**时，系统不放开权限，也不简单拒绝：自动给设置人发一条带卡片信息的留言，子女在留言上点「同意修改 / 同意停用」，系统执行后以子女名义给老人回一条回执；点「先不动 / 保留」则只标记已处理。

#### 4. AI 健康与政策顾问：有依据、有边界

- 统一入口「银发智伴」，老人不需要在多个智能体之间选择。
- 四类职责：健康咨询（给建议、提示风险，不诊断、不开方）、政策解读（不编造条款）、护理操作（分步骤讲清）、生活陪伴（含防诈骗提醒）。
- 回答前先查养老知识库并说明依据；知识库覆盖老年人权益保障、慢性病管理、护理规范、防诈骗四类资料。
- 急症优先：识别到急症描述时，第一句先让老人拨打 120 或点 SOS，不拖延、不展开分析。
- 回答用短句、大白话，少用大表格——这些内容会被朗读出来。
- 接入家庭数据只读工具：可查家庭成员、提醒、留言，只读不写，且严格按绑定关系过滤；AI 不会「假装已经帮老人建好提醒或发过留言」。
- 支持 DeepSeek、SiliconFlow、OpenAI 兼容、Anthropic 等多模型切换。

#### 5. 紧急求助：从「喊一声」到「家人知道」

- SOS 浮动按钮：弹窗内以大字号显示 120、110 和已绑定家人的电话，可一键拨号；点「通知家人」后事件落库，并向每一位处于生效绑定状态的子女发送「【紧急求助】」留言。
- 10 分钟内重复求助只落一条事件，不重复轰炸家人。
- 老人可点「我没事了」撤销本次求助，系统同时给家人补发一条安抚留言，避免家人白跑。
- 聊天中的急症关键词是第二条通道：内置 7 类急症、44 个关键词（心血管、脑血管、跌倒外伤、呼吸困难、意识障碍、严重出血、心理危机）。命中后先弹出安全提示与处置建议，**由老人点「通知家人」才真正外发**，防止误报；提示不阻断老人继续向 AI 描述情况。
- 子女端以未处理横幅置顶展示；没有绑定家人时事件仍会落库，并明确提示老人先让家人绑定。

#### 6. 老年评估与护理计划

- 内置 `elderly-assessment` 技能：Barthel 日常生活能力 10 项、MMSE 简版认知筛查、跌倒风险 6 项因素、MNA-SF 营养状况、GDS-5 情绪状态，给出分级与「建议就医 / 改善环境 / 调整饮食」等建议。
- 内置 `care-plan-generator` 技能：按日常照护、饮食、运动、用药、安全防跌倒、定期复查六部分生成个性化护理计划。
- 评估结果仅作参考，明确不替代专业医疗判断；高风险项一律建议就医或寻求专业帮助。

#### 7. 平台与交付

- Docker Compose 一键启动，开发环境热重载；知识库、模型、权限、任务中心均为可配置能力。
- 提供三个 seed 脚本，一条命令生成完整演示故事：王秀兰（老人）与王小明（子女）已绑定，5 条提醒、过去 6 天 17 次完成 / 2 次漏服、4 条留言、1 条已解除的 SOS，打开即可演示。
- 架构按路由层、服务层、仓储层分开，养老业务可继续扩展到社区、机构与多老人照护场景。

### （五）典型流程

**场景 A：早晨吃药。** 子女建「每天 8:00 吃降压药」→ 8:00 老人端弹窗、响铃、播报「早上八点整，提醒您吃降压药」→ 老人点「我收到了」→ 吃完点「做完了」→ 子女端今日状态与近 7 天完成率同步更新。

**场景 B：老人想改提醒。** 老人说「把吃药提醒改到下午三点」→ 若是自己建的，直接改；若是子女建的，系统留言转达 → 子女在留言卡片点「同意修改」→ 老人收到「已改到 15:00」的回执。

**场景 C：夜间不适。** 老人说「胸口疼」→ 弹出安全提示，建议立即拨打 120，并提供「通知家人」→ 老人确认后，子女端出现红色横幅与【紧急求助】留言 → 老人缓过来后点「我没事了」→ 事件解除，家人收到安抚留言。

## 二、作品创新性

本作品的创新不在于「接入了大模型」，而在于把大模型放进养老场景的真实约束里：老人不会用复杂界面，说错一句话可能耽误事，家人需要协同，AI 又绝不能越界。围绕这些约束，形成了以下创新点。

### 创新点一：把「提醒」做成家庭照护闭环，而不是一次性通知

行业里常见的养老提醒产品，做完「到点响一声」就结束了：老人有没有做、做得怎么样、子女知不知道，都是断的。本作品把链路补全为 **提醒设置 → 到点提醒 → 老人确认 → 执行记录 → 依从率 → 异常转达** 六个环节：

- 执行记录有完整状态机（待提醒、已提醒、已确认、已完成、未完成、漏服），而不是一个「已读」标记；
- 漏服判定留有宽限期，避免把「刚过点还没看到」误记成漏服；修改提醒时间后会清理当天失效的「幽灵待办」，不让统计失真；
- 子女端看到的是近 7 天完成率与逐日趋势，而不是零散消息；
- 老人想改子女设置的提醒时，不放开权限、也不硬性拒绝，而是走「留言转达 → 子女确认 → 回执」的协商流程。

这让照护从「我提醒过你」变成「我们一起把这件事做完」，并且全程可追踪、可复盘。

### 创新点二：一句话办事采用「规则优先」的克制型 AI，而不是把所有事交给大模型

老人说「提醒我明天早上八点吃药」，系统毫秒级完成解析、落库、刷新，不调用大模型、不消耗 token；说「怎么给小明发消息」，系统识别为提问，交还 AI 回答，不会真的把消息发出去。

这一取舍是刻意的：

- **老人等不起**：一次大模型 function calling 多一轮推理，对「改用药提醒」这种操作太慢；
- **写操作不能不确定**：模型可能把疑问句当命令执行，造成误发留言、误改提醒，这是数据事故；
- **规则可测试**：建、改、停、确认、完成、留言、导航都有明确的输入输出，可以写单测覆盖；
- **不确定就不猜**：对「大后天」「隔天」「每月」等未支持的时间表达，系统追问而不是猜一个时刻——用药提醒错一次就是安全问题；
- **权限只在服务端**：所有写操作复用 `assert_can_view` / `assert_can_target` 这套单点校验，前端无法绕过；提醒的确认与完成只能由被提醒的老人本人操作。

在该确定的地方确定，在该生成的地方生成，这是「AI 原生但克制」的交互范式。

### 创新点三：适老化不是「放大字号」，而是重构信息通道

多数产品的适老化停留在把字调大。本作品针对老人的真实使用方式，把「看」扩展为「听、说、按」：

- 到点提醒同时有弹窗、铃声和中文语音，不看屏幕也知道要做什么；
- 语音播报把「17:39」读成「下午五点三十九分」，而不是逐位念「一七三九」；播报内容包含时间、事项和说明；
- 自动朗读 AI 回复与提醒语音播报是两个独立开关——老人可能只想听到点提醒，不想听 AI 念长回复；
- 提醒语音与铃声默认开启，并在设置页提供试听，老人当场就能确认音量与语速；
- 同一分钟多条提醒去重、依次播报；页面切到后台暂停轮询，回来立即补刷，既不漏提醒也不空转；
- 支持语音输入、三档字号、四套主题色与深色模式，操作控件统一使用大号尺寸。

### 创新点四：应急链路「双通道、可确认、可撤销」

- **双通道**：SOS 主动求助 + 聊天中的 7 类急症关键词被动识别，覆盖「来不及找按钮」和「不知道这是急症」两种情形。
- **可确认**：关键词命中不自动外发，先给出分类、处置建议和「拨打 120」提示，由老人点「通知家人」才通知——既避免误报惊动全家，也避免系统替老人做决定；提示不阻断对话，AI 仍可继续回应。
- **可撤销**：老人点「我没事了」即可解除事件，系统给家人补发安抚留言，解决「虚惊一场后家人还在赶来」的现实问题。
- **有节制**：10 分钟冷却去重，避免连续求助刷屏；没有绑定家人时事件仍落库并明确提示，不让求助石沉大海。
- **有兜底话术**：急症场景第一句话是拨打 120 或点 SOS，不诊断、不分析、不拖延。

与「自动报警」相比，它兼顾了灵敏度与误报成本；与「只弹提示」相比，它真正把消息送到了家人端。

### 创新点五：角色化授权与照护伦理设计

- 绑定必须由老人本人同意，任一方都可解除；子女只能看到自己绑定的老人，不能越权查看。
- 老人自己创建的提醒，子女只能查看、不能修改；子女创建的提醒，老人想改则走协商转达，而不是默认放开权限。
- **完成率只给子女看，不给老人看**：老人端只呈现「今天要做什么」，不做完成率统计，避免把陪伴变成考核、把提醒变成压力；子女端才需要依从率来判断是否需要介入。
- AI 对家庭数据只有只读工具，不会替老人「假装已建提醒、已发留言」。

这层设计回答了一个常被忽略的问题：家庭照护系统里，谁有权看、谁有权改、什么不该给老人看。它既是权限设计，也是照护伦理。

### 创新点六：可信知识与合规边界内嵌到产品里

- 养老知识库覆盖权益保障、慢性病管理、护理规范、防诈骗四类资料，回答先检索、再说明依据，降低「张口就来」的风险。
- 人设与提示词明确四类职责与禁区：健康咨询不诊断、不开方，政策解读不编造，护理操作分步骤，生活陪伴带防诈提醒。
- 回答刻意使用短句、大白话、少表格，因为内容会被语音朗读；不确定时明确说不确定，并建议就医或咨询专业人员。
- 急症识别、SOS、家人通知构成「风险提醒—建议就医—联系家人」的合规链路，而不是由 AI 给出医疗结论。

### 创新点七：可复制的工程底座与演示能力

- Docker Compose 一键部署，知识库、模型、权限、任务中心均可配置；三个 seed 脚本一条命令生成完整养老故事，答辩现场不依赖临场造数据。
- 路由层薄、业务在服务层、查询走仓储层，养老业务与平台能力解耦，便于从家庭场景扩展到社区、机构。
- 多模型可切换，避免绑定单一供应商；知识库、文档解析、图谱等能力可随场景逐步启用。

### 创新性边界说明

## 三、填表用精简版

### 作品功能（约 300 字）

「银发智伴」面向居家养老，采用老人端 / 子女端双端设计。老人端提供今日提醒、到点弹窗 + 铃声 + 中文语音播报、一键「我收到了 / 做完了」、语音输入与自动朗读、三档字号与四套主题、问 AI 页的 SOS 与家人入口；子女端提供绑定老人、新建 / 修改 / 删除提醒、确认老人的改时 / 停用申请、查看今日状态与近 7 天完成率、留言与紧急横幅。老人可用一句话建 / 改 / 停提醒、确认完成、给家人留言、打开页面；AI 顾问基于养老知识库回答健康、政策、护理与生活问题并说明依据，急症优先提示拨打 120；系统识别 7 类急症关键词并通知家人，支持撤销。另内置老年综合评估与护理计划生成能力。

### 作品创新性（约 350 字）

一是把提醒做成家庭照护闭环：提醒—到点—确认—记录—依从率—转达六环相扣，老人一键执行、子女一屏可见。二是一句话办事采用「规则优先」而非纯大模型：几十毫秒、零 token、可单测，问句不误执行，不确定的时间不猜，写操作在服务端鉴权，兼顾老人耐心与数据安全。三是适老化重构信息通道：中文口语化时间播报、铃声与语音分离、默认开启、去重与暂停轮询。四是应急「双通道 + 人工确认 + 可撤销」：SOS 与关键词识别，关键词命中先提示、老人确认才通知，10 分钟去重，子女端横幅，老人可「我没事了」。五是角色化授权与照护伦理：绑定需老人同意、子女仅见绑定老人、老人自建提醒子女只读、完成率只给子女看，避免陪伴变考核；改他人提醒走「转达—确认—回执」协商。六是可信知识与合规：知识库检索 + 依据、不诊断不开方、家庭数据只读工具。作品基于开源 Yuxi 平台二次开发，复用智能体运行时与知识库底座，双端业务、提醒闭环、指令路由、应急链路与适老化交互为自研。
